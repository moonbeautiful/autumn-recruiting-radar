# 来源与核验策略

## 目标

先提高发现覆盖面，再用官方页面提高可信度。不能因为某个聚合来源容易访问，就把它伪装成企业官方信息。

## 分阶段流式发现（先出结果，别让用户干等）

第一性原理：**用户等的不是“所有公司搜完”，而是“下一个能投的岗位”。** 因此不要先把队列跑完再交付，要边搜边给。公司总量再大，用户的等待也只等于“搜完第一家”的时间。

参数在 `config/project.json` 的 `discovery` 段。

**阶段划分（按价值密度先出）**

1. **发现队列**：用聚合 / 榜单 / 高校就业网等“一次带出几十家”的 `platform` 线索页，按用户的城市＋岗位＋所选公司类型，实时搜出一批在招公司，形成有序队列；这批线索可先作“初筛版（待核验）”回给用户。
2. **逐家核验**：按队列顺序，对命中公司回官网 / 公众号核验，补薪资、截止、关键词、状态；每搜完一家就追加回聊天。
3. **长尾补全（可选）**：问用户是否继续扩到独角兽 / 垂类；说“继续”才扩。
4. **日常增量**：次日起只跑增量，老公司老岗不重搜。

**展开维度**（把用户给的 3 个词切成可并行的小任务）：

- 岗位同义词：`AI产品经理` → AI应用 / 大模型 / AIGC / AI策略产品经理…（成本最低，随手命中）；
- 时效状态：最新发布 / 在招 → 快截止 → 存量（用户最想先看“新的、还能投的”）；
- 公司梯队：由用户选的公司类型决定，用 `employer_anchors` 排序让知名公司先出。

**公司队列不写死**：`employer_anchors` 只作排序锚点和偶发兜底；主名单永远来自本次实时搜索，以适配任意城市与公司类型（例如用户选“哈尔滨”或“AI独角兽”，写死名单就会答非所问）。

**用户视角**：选完公司类型后，看到的是“搜完一家出一家、越等越多、随时可喊停”，而不是转圈等全部。全程不暴露“阶段 / 队列 / 锚点 / 漏斗”等内部词。

## 只允许三类来源

| 等级 | 典型来源 | 用途 |
| --- | --- | --- |
| `official` | 企业校园招聘官网、企业招聘系统岗位详情页、企业在飞书/北森/Moka 等的官方投递页 | 最终核验和投递链接 |
| `official_wechat` | 企业官方招聘公众号的公开招聘公告 | 发现招聘启动、发布时间和官网入口 |
| `platform` | 牛客、51job 校园、智联校园、猎聘校园、实习僧、高校就业网转载 | 扩大覆盖面和发现新公司 |

**禁止把聚合导流页 / 媒体报道作为岗位来源**（如 OfferShow、WonderCV、数数求职、offershow、各类“校招汇总”导流站、公众号第三方转载、新闻媒体）。这类链接点进去往往跳到非官方平台，`source_tier` 没有 `other` 这一档，写了会被脚本直接拒绝。它们只能作为“线索”帮助你找到上面三类真实来源，找到后必须用三类之一填写 `source_url`，且 `alternate_sources` 里的链接同样只能是这三类。

项目配置中的来源权重决定同一岗位保留哪个主来源。

## 发现流程

根据用户的届次、岗位、城市、招聘类型、公司类型和行业偏好生成查询，按上面“分阶段流式发现”执行：先实时搜出公司队列，再逐家核验、流式追加。发现队列与逐家核验都可并行，但受 `discovery.stream.max_concurrent_lookups` 限制。可搜索的来源组：

1. 聚合 / 榜单 / 高校就业网转载（`platform`，用于一次带出多家、形成队列）；
2. 企业官方招聘官网和官方招聘公众号（用于逐家核验补全）；
3. 牛客求职与校招板块；
4. 51job 校园、智联校园和猎聘校园；
5. 实习僧、公开招聘名单和时间表。

每组返回结构化岗位，不在发现阶段进行过度硬过滤。某个来源无法访问时返回空结果，并记录失败原因。

## 官方核验

对非官方结果：

1. 使用公司名、岗位名、届次查询企业招聘官网；
2. 找到岗位详情页后，核对公司、岗位、城市、招聘类型和届次；
3. 从页面原文读取发布时间、截止时间和岗位亮点；
4. 官方详情页成为主来源，原来源进入 `alternate_sources`；
5. 如果官网明确写“已结束”“停止招聘”“职位已下线”等，写入 `source_status: closed`；
6. 如果页面明确可投递，写入 `source_status: open`；
7. 无法判断则写 `unknown`。

每次最多深入核验 5 家新公司。没有官方详情页时保留原来源，不丢弃有价值线索。

## 时间字段

- 页面明确标注发布时间才填写 `published_at`；
- 页面明确标注截止日期才填写 `deadline`；
- 只有月份、没有具体日期时写 `unknown`，原文可放进 `match_evidence`；
- 不根据 URL、搜索摘要时间或经验猜测日期；
- 日期统一写 `YYYY-MM-DD`。

## 城市字段

- 保留页面原始城市信息；
- 多城市使用` / `分隔；
- “全国”“多地”“不限城市”保留原文；
- 完全无法判断写 `unknown`；
- 用户配置了目标城市时，“全国/多地/不限城市”仍允许匹配。

## 招聘类型

- 正式校招、应届生全职、管培生：`campus`；
- 普通实习、日常实习、暑期实习：`internship`；
- 明确写实习转正、留用实习：`conversion`；
- 同时出现多个类型时拆成独立记录，避免一条记录语义不清。

## 岗位亮点

只提炼页面可核验的信息，例如：

- 接受的专业或背景；
- AI相关职责；
- 培养、轮岗或转正机制；
- 业务方向；
- 明确的技能要求。

不得添加“高薪”“发展好”“竞争小”等无来源判断。

## 访问边界

- 只访问公开页面；
- 不登录用户账号；
- 不使用 Cookie、内部接口或隐藏参数；
- 不绕过验证码、频率限制或反爬；
- BOSS直聘、拉勾等强登录来源不作为默认每日来源；
- 单一来源失败不影响其他来源继续运行。

## 子任务返回格式

每条必须包含：

```text
company
title
city
graduation_year
employment_type
published_at
deadline
source_status
source_url
source_name
source_tier
requirements
match_evidence
highlights
alternate_sources
fetched_at
```
